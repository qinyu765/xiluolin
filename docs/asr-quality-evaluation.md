# 语音识别质量评测与桌面验收

本文档定义 XiLuoLin 短语音输入的质量门槛、数据集维护方式和桌面验收清单。它不把未经执行的手工测试标记为通过。

## 当前产品边界

- 单条语音输入最长 28 秒；25 秒时提示，28 秒自动停止并识别。
- 智谱 `glm-asr-2512` 是质量优先默认模型；智谱原生热词最多发送前 100 个稳定去重词。
- OpenAI ASR 的 `prompt` 和本地 Whisper 的 `initial_prompt` 是软提示，不等价于智谱原生热词。
- “原文听写”只清理首尾和异常空白，不调用文本整理 Provider；其他人格继续使用润色流程。
- “原文听写”不会替 ASR 改写或纠正术语；评估原文质量时必须使用原始 ASR 结果，并记录启用热词及其顺序。
- 第一阶段不提供边说边出字。实时预览必须在本阶段指标稳定后另行验证。

## 自动化基准

公开仓库提供 [`evals/asr/`](../evals/asr/README.md) 下的 80 条录制模板、JSON Schema 和聚合指标工具。真人 WAV、预测正文与报告属于私有评测数据，不进入 Git。

每轮必须固定：

- 应用 commit、ASR Provider、模型和配置；
- 麦克风与采样设备；
- 热词列表及顺序；
- 网络条件与录音环境；
- 同一份人工复核 reference。

运行 `pnpm eval:asr` 后检查：去标点 CER ≤ 8%、热词精确召回率 ≥ 95%、标点 F1 ≥ 85%、原文 P95 ≤ 4 秒、润色 P95 ≤ 7 秒。缺样本、缺类别、音频不存在或延迟数据缺失都不能算验收通过。

只有默认模型连续两轮未达标时才启动候选评测。候选必须相对默认基线降低 CER 至少 15%，热词召回不低于基线且仍达到 95%，同时保持延迟目标，才允许进入默认模型切换评审。

## macOS Fn 与录音桌面验收

在设置页开启“按住 Fn 录音”前先授予麦克风和辅助功能权限。逐项记录应用 commit、macOS 版本、设备、结果和证据：

- 短按 Fn（少于 300ms）：录音取消，临时 WAV 删除，不触发 ASR。
- 长按 Fn：按下立即出现录音状态，松开进入识别并向原目标输入框投递。
- Fn 与 Command、Option、Shift、Control 组合：本次暂存录音取消，组合键行为保持可用。
- 撤销辅助功能权限：独立 Fn 注册失败并给出提示，原长按/切换组合快捷键继续可用。
- 重新授权并保存开关：独立 Fn 恢复；不需要修改 `AppleFnUsageType` 或其他系统偏好。
- 录音达到 25 秒：出现剩余 3 秒提示；达到 28 秒：自动停止且只触发一次识别。
- 快速手动松开与 28 秒自动停止竞态：只产生一条完成事件和一条历史记录。
- 首尾各说一个短音节：确认开始和结束没有截断。
- 切换设置中的麦克风：下一次录音使用新设备；设备失效时回退默认设备并给出日志提示。
- 停止录音后 10 秒内：macOS 控制中心不得继续将 XiLuoLin 列为当前麦克风使用者，进程采样中不得残留 XiLuoLin 的 CoreAudio 输入回调。

## 连续录音资源验收

同一台设备连续执行 100 次 3–5 秒录音，交替使用完成和短按取消：

1. 每 10 次观察一次系统麦克风占用、应用内状态和录音目录。
2. 100 次内不得出现设备被永久占用、无法重新打开、重复完成事件或临时 WAV 泄漏。
3. 完成后立即切换麦克风并再录制两次，确认旧 Stream 已释放。
4. 失败时保留脱敏日志、迭代编号和系统音频设备状态，不提交真实录音。

## Node.js 热词专项验证

使用同一段私有固定 WAV（例如“请用 Node.js 写一个 HTTP 服务”）运行两组原始 ASR：

1. 不启用 `Node.js` 热词，重复 20 次。
2. 只启用精确的 `Node.js` 热词，重复 20 次。
3. 目标是热词组至少 19/20 次输出准确的 `Node.js`；未达标时记录为 Provider 能力限制，不改变“原文听写”语义，也不通过文本模型静默替换。

这些桌面检查无法由无物理按键、无麦克风授权的 CI 替代。发布说明必须明确列出已执行的平台和仍未执行的项。
